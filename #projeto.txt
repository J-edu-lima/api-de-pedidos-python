# MVP da API de Pedidos

## Entidades

### Cliente

- `id`: inteiro
- `nome`: texto obrigatório
- `numero`: texto obrigatório
- `ativo`: booleano para exclusão lógica

Um cliente pode ter muitos pedidos. Um pedido pertence a um único cliente.

### Produto

- `id`: inteiro
- `nome`: texto obrigatório
- `descricao`: texto opcional
- `valor`: decimal não negativo
- `ativo`: booleano para exclusão lógica

### Pedido

- `id`: inteiro
- `cliente_id`: referência para cliente
- `estado`: `Pendente`, `Concluido` ou `Cancelado`
- `data_entrada`: gerada automaticamente pelo servidor
- `data_entrega`: data opcional
- `entrega`: objeto opcional; sua ausência representa retirada no local
- `itens`: lista de itens do pedido
- `valor_total`: calculado pelo servidor

### Entrega

- `endereco`: texto obrigatório quando a entrega existir
- `valor`: decimal não negativo, padrão `0.00`

### ItemPedido

- `produto_id`: referência para produto
- `quantidade`: inteiro maior que zero
- `valor_unitario`: copiado do produto no momento da criação

Um pedido pode ter muitos produtos e um produto pode aparecer em muitos pedidos. O mesmo produto pode aparecer mais de uma vez no pedido por meio da quantidade.

## Regras de negócio

- O total do pedido é a soma de `quantidade * valor_unitario` dos itens mais o valor da entrega.
- Produtos e cliente devem existir e estar ativos ao criar um pedido.
- O estado inicial é `Pendente`.
- As únicas transições permitidas são `Pendente -> Concluido` e `Pendente -> Cancelado`.
- Pedidos concluídos ou cancelados não podem mudar de estado.
- Pedidos pendentes não podem ser excluídos.
- Cliente ou produto relacionado a pedido pendente não pode ser excluído; a exclusão dos cadastros é lógica.

## API

A API usa FastAPI, SQLAlchemy, SQLite e Pydantic. As rotas de negócio são versionadas em `/api/v1` e usam substantivos no plural e letras minúsculas:

- `/api/v1/clientes`
- `/api/v1/produtos`
- `/api/v1/pedidos`
- `/api/v1/pedidos/{id}/estado`

Operações disponíveis: criação, listagem, consulta individual, atualização parcial e exclusão. A API retorna `201` para criação, `200` para consulta/atualização, `204` para exclusão, `404` para recurso inexistente, `409` para conflito e `422` para payload inválido.

## Arquitetura

```text
app/
├── api/routes/       # controllers HTTP
├── core/             # configuração e banco
├── modules/          # modelos SQLAlchemy
├── schemas/          # contratos Pydantic
├── services/         # regras de negócio e persistência
└── main.py           # inicialização da aplicação
tests/                # testes automatizados
```

O frontend Flet não faz parte deste MVP. Os testes automatizados usam `pytest` e o arquivo `teste.ipynb` fica disponível para experimentos manuais.
